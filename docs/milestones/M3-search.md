# M3 — 検索

> 派生ドキュメント。正本は [PLAN.md](../../PLAN.md) / [DESIGN.md](../../DESIGN.md)。横断ルールは [00-core-principles.md](../00-core-principles.md)、型は [data-model.md](../data-model.md)。

## ゴール（PLAN §7 M3）
現在メモ内検索・置換・正規表現（CodeMirror 内で完結）、全文検索メモリ内インデックス（起動時構築 + 経路① 差分更新）、検索履歴、結果ジャンプ。

## 依存関係
- 先行: M1（ファイル層コア。全メモ走査・読込が必要）。M6 の暗号化とも関わる（暗号化メモは本文をインデックスに含めない）が、M3 時点では `.txtenc` はメモ名のみを対象とする方針で先行実装可能。

## このフェーズで扱う IPC チャネル（PLAN §2.3）
| チャネル | 引数 | 返却 | 説明 |
|----------|------|------|------|
| `search:global` | `{ scope, query, options }` | `SearchHit[]` | 全文検索（メモリ内インデックス）。scope=all/currentTab。暗号化メモは名前のみ対象 |
| `search:history:get` / `search:history:add` | – / `{ query }` | – | 検索履歴 |

- **現在メモ内の検索・置換・正規表現・インクリメンタルはレンダラの CodeMirror 内で完結し IPC 不要**（DESIGN §2.4）。
- 通知: `evt:indexUpdated`（検索インデックス更新。UI 側の再検索が必要な場合, PLAN §2.7）。

## このフェーズで扱う型/データ構造
- `search:global` の返却 `SearchHit[]`（PLAN §2.3。具体フィールドは developer 判断。少なくともヒットしたタブ/メモ名・一致箇所へジャンプできる情報を含める）。
- 検索対象: `.txt` はメモ名＋本文、`.txtenc` は**メモ名のみ**（本文は常に除外）。

## このフェーズで扱う処理フロー

### 起動時のインデックス構築（PLAN §5.1 step 4）
- `searchIndex.build`: 全タブの全メモを走査。`.txt` はメモ名＋本文、`.txtenc` は**メモ名のみ**をインデックスへ（本文は常に除外, DESIGN §2.4）。
- **ブロッキングについて（Fix11）**: v1 は DESIGN §4 の想定規模（数百〜数千メモ）ではこのステップを UI 表示前にブロッキングで構築しても許容範囲。ただし将来メモ数が大きく増えた場合は「UI 表示後にバックグラウンドで構築（完了まで検索を段階的に有効化）」方式へ変更する余地を残す（構築処理を起動シーケンスから分離しやすい形で実装しておく）。

### インデックス差分更新の 2 経路（重要・DESIGN §2.4）
インデックスの更新経路を明確に 2 つに分ける。M3 では**経路①**を実装（経路②=監視経由は M4）:
1. **経路①（アプリ内変更）**: 保存・リネーム・削除・移動・コピー・複製・暗号化変換など。**ファイル監視イベントを経由せず、保存処理の完了時にアプリ側から直接インデックス更新関数を呼んで反映**（同期的、または保存完了直後）。→ M1/M2 の各保存・操作フローの完了点で `searchIndex.updateMemo` 等を呼ぶ。
2. **経路②（外部からの変更）**: ファイル監視（chokidar）経由でのみインデックスへ反映（M4）。
- この分離により §3.3 の自己発火除外（アプリ発の監視イベントは破棄）と矛盾しない。アプリ内保存イベントは監視側で破棄されるが、インデックスへは経路①で直接反映されるため、**編集直後の全文検索が古い本文にヒットし続ける不具合を防ぐ**。

### 暗号化メモの扱い（DESIGN §2.4）
- 暗号化メモは、**ロック解除中（編集中）かどうかに関わらず、常に本文をインデックスに含めない**（対象はメモ名のみ）。復号平文をインデックス構造に持ち込まない（平文露出の最小化原則）。

## このフェーズで扱うディレクトリ/ファイル（PLAN §3）
- `src/main/search/searchIndex.ts` — メモリ内軽量インデックス（構築・2 経路差分更新。M3 は構築+経路①）
- `src/main/ipc/searchHandlers.ts`
- レンダラ `src/renderer/components/Search/` — 現在メモ内検索・置換 UI、全文検索パネル、結果ジャンプ、検索履歴

## このフェーズのエラーハンドリング（[00-core-principles.md](../00-core-principles.md) §8）
- 検索は基本的に読み取り操作。IPC 境界での `Result`/`UNKNOWN` 丸めは共通どおり。特有の新規エラーコードは無い。
